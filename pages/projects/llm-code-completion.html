LLM Code Completion Research

During my research internship at REALISE Lab, Concordia University, I investigated how selecting, organising and ordering repository context affects the quality of code completions generated by Large Language Models (LLMs). Our experiments contributed to the JetBrains ASE 2025 Context Collection Challenge and a first-author research paper.

My focus: Information retrieval, experimental design, retrieval evaluation, result analysis and research communication.

01 / The Problem

Code completion models often need information from elsewhere in a repository to produce a useful suggestion. However, large repositories can contain more code than fits within an LLM's context window. Irrelevant or poorly arranged context may also reduce completion quality.

Our research asked: Which repository information should be retrieved, how much should be included, and in what order should it be presented? We focused on improving the context provided to existing LLMs rather than training a new code-generation model.

02 / My Research Approach

We designed experiments around repository-level, fill-in-the-middle code completion. The model is given the code before and after a missing segment (the prefix and suffix), together with additional context retrieved from the repository.

  • File-level retrieval: Investigated selecting relevant source files using lexical retrieval techniques including BM25.
  • Context size and ordering: Varied how much retrieved content was supplied and where it appeared in the prompt.
  • Chunk-level retrieval: Explored retrieving smaller, code-aware segments using static analysis, rather than always supplying entire files.
  • Experimental evaluation: Compared retrieval settings against file-level and no-context baselines using the code-completion task and evaluation framework.

03 / Evaluation & Findings

We assessed completion quality using chrF, a character n-gram F-score comparing generated code with reference completions. This enabled quantitative comparisons between different context retrieval strategies.

In the initial Python experiments, chunk-based retrieval using static analysis achieved a 6% improvement over our best file-level strategy and a 16% improvement over the no-context baseline , as reported in our research paper.

We also found that more context was not always better. Retrieval granularity and the ordering of information in the prompt influenced performance, showing that relevant context needs to be selected and composed carefully.

Our team placed third in the Python track of the JetBrains challenge. The work also contributed to the research paper Beyond More Context: How Granularity and Order Drive Code Completion Quality.

Interpreting the results: The +6% and +16% figures describe the initial-phase Python experiments, not the final private competition score. chrF measures similarity to reference completions; it does not, by itself, establish functional correctness or usefulness to a developer.

04 / My Individual Contribution

I worked with researchers at REALISE Lab on the design, implementation and analysis of context-retrieval experiments.

  • Investigated file-level and chunk-level retrieval approaches for repository context.
  • Implemented and compared retrieval experiments, including variations in context size and ordering.
  • Analysed evaluation results and interpreted trade-offs between retrieval strategies.
  • Communicated our findings through a research paper as first author, alongside my co-authors.

05 / Reflection & Limitations

This research strengthened my understanding of information retrieval, code-aware context selection, LLM evaluation and experimental design. One important lesson was that improving an AI application does not always mean training a different model: how information is retrieved and presented can make a substantial difference.

The results were obtained within a particular benchmark, set of languages and evaluation protocol. Higher chrF scores do not guarantee that generated code will compile, pass tests or be accepted by developers.

Future work could evaluate functional correctness, developer usefulness, inference cost and retrieval performance on larger or more diverse repositories.
